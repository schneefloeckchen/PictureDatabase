Memory Leak

Nov 24 entdeckt, tritt erst nach längerem import auf. Steps:

  1. Test Umgebung, skript zum löschen der Dev Datenbank, dann import mit dem Verzeichnis, in dem Klara iPhone Bilder liegen (20GB).
  2. Nachdem alle Files aus dem import in einem Verzeichnis liegen, gibt es einen:
    java.lang.IllegalArgumentException: Self-suppression not permitted Fehler.
    In Bugdatabse ist Eintrag dazu, works as designed. Ist spezielles Verhalten in einem try mit resource, die einen auto-close beinhaltet. https://bugs.java.com/bugdatabase/view_bug?bug_id=8317229
  3. Baue extra Testcase, der 20000 oder mehr Pictures (ohne datei erzeugt / Dummies) in ein oder mehrere Folder packt. Funktioniert soweit.
  4. Da auch der obige Fehler von vollgelaufenem Heap angekündigt wird, suche weiter im gc. In https://www.baeldung.com/jvm-garbage-collectors Intro dazu, die gcs werden per aufruf parameter ausgewaehlt und ggf. Konfiguriert. Testing the different GCs, switches are for the java VM, addes to the run properties in NB
    1. -XX:+UseZGC - still memory leaks
    2. -XX:+UseParallelGC - memory leaks
    3. -XX:+UseParallelGC -Xmx12192m -- lis working, used memory till ca 7.xx GB, is deleting objects, shows expected behavior.
  5. Nicht gc Problem, da die Pic Objecte and dir PicDir angebunden sind, bleiben die im Speicher bis das PicDir geloescfht wird.
  6. Neuer Anlauf: PersistentSet!
